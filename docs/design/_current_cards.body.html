现在用的是什么

17 处内容卡片的真实 class 字符串，逐字来自源码

没有组件。每个页面自己写一个 <section>（或 <div>）， 套四个工具类：圆角、边框、底色、内边距。卡片自己的第 4 个维度——内部行距——不在容器上， 而是由卡内每个子元素用 mt-* 自己带（这正是与 CardComponent 的结构差）。

  <div class="flex items-center gap-2">…标题 + <ScopeBadge/>…</div>
  <dl class="mt-3 grid gap-x-6 gap-y-2 …">          <!-- ↑ 12px 由子元素给 -->
</section>

<!-- 卡片与卡片之间也不在组件上：settings 各 tab 用 mt-3 / mt-5 / mb-4 -->

<!-- 项目子页是外层列给间距（space-y-5 = 20px），卡片自身不带外边距 -->
<div class="mx-auto max-w-4xl space-y-5">
  <section class="rounded-2xl border … p-4">…</section>
  <section class="rounded-2xl border … p-4">…</section>

04

结论（修正我之前的说法）

之前说"只有圆角不同"只在一种前提下成立

我先前在设计稿里写"唯一会改变画面的差异是圆角（16→8px）"。这话只在一种前提下成立： 换组件时把卡内子元素的 mt-* 原样留着、不接卡片的 body 行距。而按组件的设计 （body 是 gap:12px 的 grid），行距会归 统一 12px——于是当前的 2px / 4px / 8px / 12px / 16px 五档节奏会全部被抹平，标题与说明之间会从 2–4px 拉开到 12px。

所以真实取舍是两条路，不是"换个类名"：

维度现在（17 处手写）换 CardComponent（按组件设计）只收圆角（不引入组件）
圆角16px8px8px
内边距16px16px16px
底色 / 边框#FFFFFF / #E4E7EC#FFFFFF / #E4E7EC不变
内部行距2 / 4 / 8 / 12 / 16px 逐处不同统一 12px（节奏被改）不动
代码形态每页一行工具类17 处改组件 + 删被接管的 mt-*17 处类名一改（半小时）
风险—每处都要目验间距（17 处视觉改动）零结构风险
注意一处实测发现：左边那张"现在"的卡片与组件卡片并排看，差别**不止圆角**—— 标题与说明之间的距离在现在这里是 2px（mt-0.5），在组件里是 12px；说明与字段之间现在 16px（mt-4）、 组件里 12px。也就是说"换成组件"这件事本身会重新排一遍每张卡内部的疏密，不只是把方角磨圆。
