规则

  • 交给其他模型执行只在项目根是 git 仓库、且至少有一个不是当前模型的已配置模型时出现。它不清上下文。
  • 挑好模型就是批准计划。主代理继续用当前模型，当技术负责人：用你挑的模型派一个 general-purpose 执行子代理；子代理在 .worktrees/<名字> 从当前 HEAD 新建 worktree 和分支，在里面按计划实施并提交到自己的分支。
  • 子代理交回后，主代理在 worktree 里重跑每条验收、核对改动范围、读完整 diff 和新测试，给出通过 / 返工（最多两轮）/ 卡住。它不合并、不推送、不动你的分支；要不要合并由你决定。
  • 主分支上没提交的改动不会进 worktree。计划涉及的文件有未提交改动时，主代理先停下来问你。
  • 请 X 再评审：不新开评审子代理，而是让上一次的那个评审子代理在它原来的会话里续聊——发给它修订后的计划全文和上次评审之后你说过的话，请它先逐条核对上轮意见是否改到位，再看新增改动。X 是它的模型；它的会话还在、模型还在列表里才出现。评审期间底栏和今天一样，只剩进度和「停止」；「查看」打开的是同一个评审对话。
