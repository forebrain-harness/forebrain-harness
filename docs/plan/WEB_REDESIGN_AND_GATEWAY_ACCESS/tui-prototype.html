渲染契约（执行时照这个，不要自由发挥）

  • 面板 = 顶部标题/副标题 + 可选 ⌕ 过滤条 + 滚动 body + 底部 faint 按键提示；面板上方一条 \x1b[90m─ 分隔线，高度恒为终端一半。
  • 行首两格缩进；选中行用 ❯（accent 110）占掉缩进。键盘在过滤条时 ❯ 消失、caret 出现，两者永不同屏。
  • 过滤条三行（空 pad / 文本 / 空 pad），底色 48;5;238；glyph 聚焦 110、失焦 245，文本聚焦 252、失焦 249，占位 244，placeholder 固定 Type to filter；可选行 <8 不显示过滤条；问句与过滤条之间、过滤条与列表之间各空一行（反馈 E，与 /model layout 一致）。
  • 两列：名字列宽 = 全量最长 label（上限 40，且不超行宽 2/5），说明列隔 2 格；任一名字超列宽则整列表改为上下堆叠，不混排。
  • 滚动提示 faint，形如 ↑ 1 more · ↓ 4 more；过滤命中排序 = 完全相等 → 前缀 → 词首 → 包含 → 说明列包含，分组标题随最佳命中保留。
  • 密钥输入：› glyph，• 掩码，仅长度 >8 时末 4 位明文；复核页 facts 标签 accent + 冒号、值列对齐。
  • 审批面板不是 slash panel：它顶掉 composer（没有 draft、没有 footer），顶部一条常驻分隔线，内容区 = 终端行数 − ⌊行数/3⌋ − 1（40 行 → 26 行）。内容超出时默认贴底，verdict 行永远在视野里；PgUp/PgDn/Home/End 翻。
  • 审批面板的选中行是加粗 > （不是 ❯），没有缩进：选项写成 1. 编号，计划正文与分隔线从第 0 列开始。分隔线 faint。
  • 评审选择器在同一 overlay 里展开：整段选项行换成问句 + 模型列表，按键提示同时换成 Esc to go back · Enter to request the review。首帧把问句带到视野顶端（问句与选中行同屏），之后按键只把选中行带进视野。
  • 模型列表照 01 页 /model 的分栏：❯（110）后跟 provider/model，行首没有序号，名字列按最长名字定宽（上限 40、不超行宽 2/5），说明列隔 2 格、是完整请求 URL，过窄时从 base 中部省略但保住路径，任一名字超列宽则整列表堆叠；列表只放已配置的模型，不提供新增入口。当前会话模型在名字后面标 ●（110）：名字列不因它变宽；端点列在它后面恒定留 1 格，其余行仍与它同列对齐。
  • 请求评审只印一行 ✔ You asked provider/model to review the plan（✔ 绿 70、正文 244），审批仍是 pending。

本期的语义（原型里已全部体现）

  • /connect 第一页三组：Sign in with a subscription / Use an API key / Custom。订阅组只放真能登录的三个：ChatGPT、OpenCode Go、Volcengine Ark。
  • 每个模型选项都带完整请求 URL：provider/model + base_url 直接拼 api_path；自定义协议不追路径，只显示 base_url。同一 provider/model 可有多行，选中值是行 id，不是名字。
  • /model 只列这个会话已配置的模型，没有新增/自定义模型的入口——添加模型（含自定义端点）统一走 /connect；说明列过窄时从 base 中部省略，路径必须保住。
  • 订阅登录 = 选订阅 → 登录 → 按套餐勾选模型 → 写库；Key 池多把则单选一把，空池经确认创建 forebrain-…。
  • 自定义模型不问 provider（恒为 custom），协议必选；模型名原样发送，可自带 vendor/ 前缀。
  • 保存前查重：四元组相同则询问是否替换 Key，不静默覆盖。
  • 选完模型后单独一页问子代理授权（是否允许主代理自己挑这个模型派子代理），单选、默认 No；订阅流程勾完模型后用多选页问同一件事。确认页多一行显示结果。

计划审批（exit_plan_mode）的语义

  • 标题 Tool approval + Tool: exit_plan_mode，下面是计划、Would you like to proceed? 和 verdict 行。行的顺序规则是同意类在前 → No → 评审类（owner 2026-11-10）：数字键跟随可见行变化，y/n/m 仍按语义跳行。
  • 交接行 Yes, hand off to another model 只在会话项目根在 git 仓库内且有其他已配置模型时出现；不出现时 No 紧跟在同意类之后，行号随可见行变化。
  • 交接语义：主代理用你选中的模型派一个执行子代理，在 .worktrees/ 下的独立 worktree 里按计划实施并提交到它自己的分支；主代理在 worktree 里重跑验收、给出结论，不碰你当前的分支。
  • 评审行 Ask another model to review this plan 只在该会话有可用模型时出现；没模型时不出现，不是灰掉、不是点了报错。工具 m 直接进选择器。
  • 再评审行 Ask provider/model to review it again 只在本会话上一次评审仍可续聊（它派出过评审子代理且模型仍配置）时出现：回车不新派评审，而是让上一次那个 plan-reviewer 在它自己的会话里续聊修订版。
  • 选评审行/交接行都不是决定：审批保持 pending，选择器在同一个 overlay 里展开，transcript 一个字都不变；Esc 回到 verdict 行，选中项不丢。交接选择器与评审选择器是同一个列表组件，只是问句与提示不同（Which model should carry out this plan? · Enter to hand off）。
  • 选择器默认预选第一个非当前模型（第二意见与换手都是这一行的意义），当前模型在名字后面标 ●。↑/↓、j/k 移动，Enter 请求评审/交接；Esc 回到 verdict 行、选中项留在原来的行。
  • 思考强度第二屏（计划 310）：在模型选择器里选中一个配了档位的模型回车，不立即决定，而是进第二屏问 Which reasoning effort should provider/model use? (Esc to go back)。单列 ❯ 光标，每行 = 英文显示名 + 可选双写档位 id（仅显示名与 id 大小写无关地不同时才写，英文里只有 Off none）+ 可选齿轮图标 ⚙（标在行配置的那一档，即「模型设置」）。
  • 第二屏的档位与排序照 Web 的 EffortChip：none/minimal/low/medium/high/xhigh/max（none 在前），显示名 Off/Minimal/Low/Medium/High/xHigh/Max（xhigh 显示成 xHigh，与引擎 EffortEnglishLabel 一致）。行没配默认档时首项是 Default（不钉任何档）；审批第二屏没有会话存档位，光标落在行的默认档。
  • 第二屏 ↑/↓、j/k 移动，Enter 才决定（评审仍 pending、交接即批准，确认行带上选中档位）；Esc 回到模型列表、选中的模型不丢，再 Esc 才回 verdict 行。模型一档都没配（efforts:[]）时跳过第二屏，选完模型直接决定。
  • /model 第二步（01 页 model-effort）与第二屏同语义，但用两列分栏（名字列 = 显示名，说明列 = 双写 id + 齿轮图标 ⚙），光标落在会话钉值而非行默认档；会话没钉值或行没配默认档时首项 Default。
  • 评审跑在 plan-reviewer 子代理里，结果只作为审批材料：它不产生 verdict，也不关闭审批，评审行仍在（可以再换一个模型）。
  • Esc 在审批面板上是拒绝（Esc to decline），不是取消整个回合；只有 Ctrl+C 是取消。

文案规则

  • TUI 文案以英文为主，沿用现有字符串；订阅/套餐名跟随注册表 Label。
  • 只说当前事实。不提被移除的配置位置与旧写法，不做「以前 / 不再」式对照——按全新产品设计。
  • Key 只露末四位；登录类行显示 Account sign-in；错误短句，不带响应体、不带任何密钥。
  • 界面不暴露内部数据文件名；模型自带能力叫 Provider default。
  • 原型是设计稿：示例模型名、地址、账号与 Key 均为虚构。
