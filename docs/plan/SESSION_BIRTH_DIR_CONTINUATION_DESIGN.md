## 0. 规则（owner 裁决汇总）

| # | 规则 |
|---|---|
| R1 | **每个会话都属于一个项目；出生目录 = 项目根 = 工作目录**。出生目录即 `fb_sessions.cwd`，创建时写一次，之后不变。 |
| R2 | **TUI**：在哪个目录启动，那个目录就是项目根，**不向上找 git 根**。该目录不在项目表里就自动登记，与 web 创建的项目同一张表 `fb_projects`、同样字段，web 端有对应的项目空间。启动目录在 FOREBRAIN_HOME 内（含其子目录）→ 拒绝启动。 |
| R3 | **web**：对话界面在对话前**必须选择一个项目或一个文件夹**。选的文件夹自己没有关联的项目（按精确根匹配，不看上级目录）→ **自动创建以该文件夹为根目录的项目**，与 TUI 启动目录自动登记同一口径（owner 2026-10-11）。创建项目时用户选哪个目录，项目根就是哪个目录：仓库子目录照样是项目，不改成 git 根。项目根不能在 FOREBRAIN_HOME 内。 |
| R4 | **gateway 启动目录只是单纯的启动目录，没有任何业务语义**：不做默认出生目录或项目，不从它推导信任/沙箱/审批，不读它的 FOREBRAIN.md 或 git 上下文，不加载它的 MCP/LSP/技能。此前"项目根不能等于 gateway 启动目录"已取消。 |
| R5 | **续聊**：两端都在会话的出生目录执行，目录不存在就拒绝。TUI 的 `/resume` 只列当前项目的会话；`resume <id>` 指向别的项目的会话 → 拒绝并提示"请在 X 中运行 `forebrain resume <id>`"。 |
| R6 | **信任**：沙箱与审批按项目根**自己的**信任记录推导，不沿用续聊端的。项目级 MCP/LSP/技能/项目设置的加载门槛**去掉"受版本控制"**，只看"受信任 + MCP/LSP 逐条同意"。 |
| R7 | **通道、定时任务移进项目空间**（菜单栏去掉这两项），属于当前项目，没有"所属项目"选项。**技能工坊两个入口**：菜单栏入口不选项目，生成的技能属于本主代理，放在主代理技能目录；项目空间入口生成的技能属于本项目，放在项目技能目录（owner 2026-10-11，取代此前"配置里必选项目"）。 |
| R8 | **附件**：web 上传（含粘贴/拖入的截图）用同一套"保存到"目录选择，可选项目根、子目录，或新建并命名一个目录；每个项目记住上次选的目录。TUI 粘贴的截图存进项目里的固定子目录 `<项目根>/attachments/`。附件和 agent 生成的交付物都在项目目录里，不在 agent workspace。 |
| R9 | **旧库迁移**：没有项目的老会话按其 `cwd` 原样建项目并归入（项目根 = cwd）；**目录不存在也照样建项目**，续聊时按"目录不存在就拒绝"处理，避免外接盘、网络盘暂时不在时被误删。**只删除 `cwd` 为空的会话**，连同消息、事件、run。出生目录在 FOREBRAIN_HOME 内的会话只有本机有、已手工删除，迁移不为此写分支。 |
| R11 | **项目的归档去掉，删除项目连同对话一起删**（owner 2026-10-11）：只保留置顶与删除，不常用的项目按修改时间沉底。删除项目时，二次确认写明将删除的对话数与定时任务数，确认后一起删（消息、事件、run、subagent 子会话、该项目的定时任务）；目录里的文件不动。项目里有对话正在运行时拒绝删除。之后在该目录启动 TUI、或在对话里选它，会重新登记一个空项目。 |
| R10 | **已执行**：本机 63 个 `cwd` 被旧版本错写成 agent workspace 的会话，已于 2026-10-11 按 owner 指示直接在本机真实库删除（不写进迁移、未做整库备份），连同级联数据与 61 条 `memory_stage1` 任务。 |

## 2. 设计

### 2.1 会话工作目录进入每一轮的上下文

- 新增 `tool.WithWorkingDir(ctx, dir)` / `tool.WorkingDirFromContext(ctx)`。runner 在每一轮入口放入**自己的项目根**，subagent 继承 ctx。
- 1.1 表里每一处改为"先读上下文，读不到再 `os.Getwd()`"；相对路径改为 `filepath.Join(工作目录, path)`。
- runner 加载时的三处（允许根、MCP 子进程目录、文件系统策略）改用 runner 的项目根。
- 不复用 `ProjectRootFromContext`：它目前只有 subagent 设置（`pkg/run/subagent.go:1113,1343,1799`），语义是"给 subagent 的路径约束提示"。实现时可以评估合并。

### 2.2 每个会话都跑在它的项目 runner 上

- **gateway**：
  - `RunnerForSession` 一律走项目条目（R1 保证每个会话都有项目）。
  - 没有项目的会话在 R9 迁移后不存在；遇到漏网的，拒绝运行，不再回落到基础 runner。
  - 基础 runner 只服务不属于任何会话的 agent 级读取（花名册、模型列表等），它的启动项目为空（R4）。
- **项目 runner 的构建**（`buildEntryLocked`）：
  - `launch := safety.ResolveRegisteredContext(home, project.Root)`：精确根，不向上找（R2/R3 两端一致）；
  - `AppCfg = safety.EffectiveConfig(原始配置, launch)`：按项目根自己的信任推导，修 1.2 的缺陷；
  - 工作目录 = 项目根（2.1）；
  - FOREBRAIN.md 与 git 上下文取项目根。
  - `Environment` 需要另存一份**未推导的原始配置**。
- **TUI**：`process.Open` 的 `LaunchDir` = 项目根，也就是启动目录。启动项目改用 `ResolveRegisteredContext`（精确根，与 web 一致），不再用向上找 `.git` 的 `ResolveProjectContext`。
  - TUI 进程的当前目录本来就是项目根，2.1 的上下文写进去的值与进程目录相同，行为不变。
  - 行为变化：在仓库子目录启动时，信任提示、计划文件目录、项目记忆都以该子目录为准，不再是仓库根。

### 2.3 去掉"受版本控制"门槛（R6）

- `TrustedRoot`、`trustedProjectRoot`、`mcp.go:80` 的分支、LSP 的 `Trusted` 判断、`skills.go:584`、`codex_assets.go:667` 改为只看"受信任"。MCP/LSP 的逐条同意保留。
- `safety.Project.VersionControlled` 字段保留：`.git` 保护路径等其他地方可能还在用，实现时逐个确认。
- 同步更新提到"trusted, version-controlled"的用户文档（`grep -rn 'version.controlled' docs README* 2>/dev/null`）。

### 2.4 TUI：启动目录登记为项目

1. 启动时（信任提示之前）规范化启动目录（`safety.CanonicalPath`）。
2. 在 FOREBRAIN_HOME 内或是文件系统根 → 打印"不能在 forebrain 的数据目录里启动，请到项目目录下运行"并以非 0 退出。校验规则与 web 的 `validateProjectRoot`（`pkg/gateway/api_extra.go:4855-4891`）共用一个函数，下沉到 `pkg/state` 或 `pkg/safety`。
3. 按 `(agent_id, root)` 找项目：
   - 找不到 → 创建（名字取目录名，`ProjectKey = memory.ProjectKey(root)`，其余字段取 web 创建时的默认值）；
4. 新会话出生时 `Cwd = root`、绑定 `project_id`。TUI 的所有会话创建路径（`pkg/tui/chat_session.go:564,1829` 一带的 `Cwd: s.home()` 是 hook 输入，另行核对）都要绑定。
5. `/resume` 列表改用 `ListSessionsForProject`（`pkg/state/session_store.go:768`）。`resume <id>` 指向别的项目 → 提示"这个对话属于项目 X（<root>），请在该目录运行 `forebrain resume <id>`"并退出；会话所属项目的根目录不存在 → 提示并退出。
6. 项目表 `(agent_id, root)` 今天只有普通索引（`pkg/state/schema.sql:24`）。TUI 和 web 可能同时登记同一目录，需要**唯一约束**：改表结构，迁移里合并重复，见 2.8。

### 2.5 web：先选项目，再对话（R3）

- **对话前必须选"项目"或"文件夹"**：对话界面在发出第一条消息前，要求二选一。
  - 选项目：从项目列表里选，默认选中上次用的项目。
  - 选文件夹：浏览本机目录选一个。该文件夹已是某个项目的根（精确匹配，不看上级）→ 用那个项目；否则**自动创建**以它为根的项目。名字取文件夹名，`ProjectKey = memory.ProjectKey(root)`，其余字段取 web 创建项目的默认值，与 TUI 自动登记（2.4 第 3 步）共用同一个"按根找或建"函数。
  - 校验与 TUI、web 创建项目一致：目录必须存在；不能是文件系统根；不能在 FOREBRAIN_HOME 内。
  - 去掉不带项目的对话入口。
- **浏览本机文件夹**：浏览器拿不到本机绝对路径，需要 gateway 提供只列目录名的接口（需鉴权，从用户主目录开始，可输入绝对路径跳转，不列 FOREBRAIN_HOME 内部）。今天的项目创建表单只有手填路径输入框（`frontend/src/views/ProjectsView.vue:48`），没有现成的目录浏览器，两处改为共用这个浏览器。
- **信任（与 TUI 同口径）**：选中的文件夹从没判断过信任时，在第一条消息前弹出与 TUI 启动时同样的信任问题（信任 / 不信任 / 取消）。web 创建项目表单今天的"信任"勾选（`ProjectsView.vue:148` 的 `trust`）保留。
- 创建项目沿用 `validateProjectRoot`，根就是用户选的目录。若该目录已是某个项目的根（包括 TUI 登记的），提示"这个目录已是项目 X"并打开它。
- start_run：项目根不存在 → `run_error`，`code = session_directory_missing`，文案"这个对话所在的目录已不存在：{dir}。无法继续。"（英文同义）。
- plan 022 的工作台根目录链（项目根 → cwd → 默认出生目录 → agent workspace）简化为**只有项目根**，022 需要改写（见第 3 节）。

### 2.6 通道、定时任务、技能工坊（R7）

- **通道**：移到项目空间的"通道"标签。每个项目配置自己的通道和凭据，同一个机器人账号只能属于一个项目。从通道进来的对话属于该项目、出生在项目根。
  今天通道配在主代理下（`pkg/config/agents.go:24` 的 `Channels`），要迁成按项目存。**按项目存在状态库，凭据写 `${变量}` 引用、值存 `~/.forebrain/.env`**（owner 2026-10-11，plan 035 方案 A）。**旧配置迁移时删掉**（owner 2026-10-11）：配置迁移删除主代理下的 `channels` 段；若有启用中的，启动时提示一次"通道需在项目空间重新配置"，不猜归属项目。本机 12 个全部未启用、无凭据。
- **定时任务**：只在项目空间的"定时任务"标签里，新建在弹窗里，`project_id` 取当前项目（`fb_cron_jobs.project_id`，`pkg/state/schema.sql:303`）。旧的空项目任务在迁移里删除（本机 0 个）。
- **技能工坊**（owner 2026-10-11 改定）：
  - 菜单栏和项目空间都不再单列入口。改从技能页进入：
    - 主代理技能页、项目空间"技能"标签的列表上方有"新建技能""发现并安装"；
    - 列表每行有"详情"，进入后改进该技能；
    - 工坊页左上角可以返回技能页。
  - **工坊页是会话页的超集**（owner 2026-10-11）：消息流、输入框（加号、Agent/计划、审批、模型、推理强度）、回到这里、心跳、工作台都和会话页是同一套组件。区别只有三处：
    - 顶栏多了面包屑、版本状态和"发布 vN"；
    - 工作台在会话页的"概览、上下文、工作目录、变更文件"之外加四个标签：测试用例、评测、触发描述、版本；还没有技能时这四个不可用。"变更文件"列出草稿相对当前版本改过的文件，每个可对比、编辑、撤销变更；
    - 输入框不显示项目选择，项目由入口决定。
    "详情"接着这个技能最近的工坊会话；顶栏可以开新会话。工作台里的新建、编辑都在弹窗里，改动只写草稿。
  - 生成位置跟着入口走：主代理入口写 `<agent workspace>/skills/<名称>/`，项目入口写 `<项目根>/.forebrain/skills/<名称>/`。只保留下载 zip；草稿也列在技能列表里。
  - **主代理级工坊对话是 R1 的唯一例外**：工作目录是主代理技能目录本身（`<agent workspace>/skills/`），以便参考其他技能；对话不属于任何项目，不进对话抽屉。项目级工坊对话属于该项目，工作目录是项目根。
  - **草稿与发布**（owner 2026-10-11）：
    - 工坊里新建的技能是草稿，放在技能加载器不扫描的位置，不会被任何会话加载；
    - 点"发布"后写进正式技能目录（主代理或项目），默认启用；
    - 只有已发布的技能能启用、禁用；
    - 修改已发布的技能会产生一份新草稿，旧版本照常使用，直到再次发布，列表里标"有未发布的修改"；
    - 草稿可以删除（丢弃）、下载；
    - 安装进来的技能（离线、在线、发现）直接算已发布。
  - **版本管理**（owner 2026-10-11 要求，细节以设计稿为准，带"待定"的项需 owner 确认）：
    - **模型**：每个技能（主代理、项目、共享三层）有一条只增不改的已发布版本序列（v1、v2…），外加最多一份草稿。每个版本记录时间、来源（新建 / 发布 / 从某来源安装 / 从某来源更新 + 上游提交号）、发布说明（可选）、相对上一版的文件改动统计。
    - **三种状态由此推出**：
      - 草稿：还没有任何版本；
      - 已发布 vN：有版本、没有草稿；
      - 有未发布的修改：有版本，同时有一份基于 vN 的草稿。
    - **所有改动只进草稿**：工坊编辑、"恢复为草稿"（把某个旧版本的内容复制成草稿）、"拉取到草稿"（上游更新）都只写草稿。只有"发布"会生成新版本，并把它的文件写进正式技能目录，这也是加载器读取的位置。
    - **删除与恢复**：丢弃草稿不影响当前版本。删除技能会删掉全部版本，需二次确认。
    - **安装与更新**：安装即 v1。在线安装、发现安装的技能记下来源，上游有新提交时标"有更新"，拉到草稿、审过后再发布。离线安装没有上游。
    - **会话与版本**（owner 已定：继续用会话开始时的版本）：今天会话开始时只冻结技能清单（名称与描述，`pkg/run/skills.go:27-36`），真正用到某个技能时才从磁盘读内容（`pkg/run/skills.go:845`）。
      改为冻结清单时同时记下每个技能的版本号，用到技能时按版本号读快照。这样不会出现清单里是旧描述、读到的却是新内容的错位。
    - **存储**（owner 已定：存技能目录旁的隐藏目录）：历史版本快照放在各层技能目录旁的隐藏目录里，例如 `<技能目录>/.versions/<名称>/v3/`，加上一份记录版本元数据的清单文件。历史跟着目录走，项目里的可以被 git 提交。
      草稿同样在磁盘上，放在加载器不扫描的隐藏位置（例如 `<技能目录>/.drafts/<名称>/`），工坊的模型用文件工具编辑它。加载器必须跳过这两个隐藏目录。
    - **正式目录的改动自动进草稿**（owner 2026-10-11）：在工作台"工作目录"树上、或会话里用文件工具，编辑 / 新建 / 删除技能正式目录（`<技能目录>/<名称>/`）里的文件，一律写进该技能的 `.drafts/<名称>/`（没有草稿就先从当前版本复制一份），在"变更文件"里看到，发布后才生效；删除整个技能目录走技能列表的"删除技能"确认。`.versions/` 不在树上显示，也不允许文件工具写入。
    - **TUI**（owner 已定：两端一致，在 `/skills` 面板里发布，不另加子命令）：终端里的 skill-workshop / skill-generator 也先生成草稿，版本记录两端共用。面板设计见 `docs/plan/SKILL_DRAFTS_AND_VERSIONS_DESIGN.md` 第 3 节。
  - **安装**：离线安装、在线安装都是技能列表上方的按钮，点开在弹窗里操作（owner 2026-10-11：在线安装单独保留，不并进发现）。"发现并安装"的候选技能直接列在回复里，可直接安装；安装后即 v1，工作台的技能标签随之可用。设置里的共享技能库没有工坊，只有离线安装、在线安装。

### 2.8 迁移（R9）

在一个状态库迁移里完成，顺序如下：
0. **删掉 `fb_projects.archived_at`**（R11），已归档的项目变回普通项目。
1. **`fb_projects` 加 `(agent_id, root)` 唯一约束**：重复根的项目合并到最早的一条，其会话、定时任务的 `project_id` 改指向它；本机为空表。
2. **没有项目的普通会话**，按 `(agent_id, 规范化 cwd)` 分组：
   - `cwd` 为空 → 删除；
   - 其余（**包括目录已不存在的**）→ 找或建项目（名字取目录名），绑定会话，`cwd` 规范化为项目根。规范化用 `safety.CanonicalPath`；目录不存在时规范化失败，就用 `filepath.Clean` 后的原值。迁移里建项目不走 `validateProjectRoot` 的"目录必须存在"检查。
3. **subagent 会话**：沿 `parent_session_id` 取父会话的项目，`cwd` 同步；父会话被删或不存在 → 删除。
4. **删除方式**：`PRAGMA foreign_keys=ON` 下删 `fb_sessions`，级联删消息、事件、run、审批、记忆抽取结果（外键见 `pkg/state/schema.sql:61-351`）；另删 `fb_memory_jobs` 里 `kind='memory_stage1' AND job_key=<session id>` 的行（无外键）。
5. 迁移结束照框架现有行为：有空页就 VACUUM（owner 2026-10-11 撤回"不自动回收"）。
6. **项目键按项目根本身生成**（owner 2026-10-11）：不再向上找 git 根（`memory.ProjectKey` 今天沿目录向上找 `.git`，`pkg/memory/scope.go:229-253`），子目录项目有自己的计划目录和项目记忆。迁移给每个项目写精确根的项目键。项目键因此变了的会话本机有 2 个（forebrain-harness 仓库下的 `docs/plan/SUBAGENT_CONVERSATION`、`docs/plan/SCHEDULED_RUNS_TRANSCRIPT`），已核实它们在 `~/.forebrain/workspace/plans/` 下没有计划文件，不需要搬文件；它们以前写进仓库根的项目记忆留在原处。

### 2.10 回到这里（checkpoint，owner 2026-10-11 已定）

- **现状的问题**："撤销最近一次文件改动"（`pkg/gateway/api_extra.go:2112-2165`）的做法，是找到会话最后一次成功的 `edit_file`/`write_file`（`pkg/state/session_events.go:423-447`），取该路径**不分会话**的最新快照覆盖回去。问题有四个：
  - 只覆盖一个文件；
  - 可能取到别的会话留下的快照；
  - 不能预览，也不能撤回这次恢复；
  - TUI 没有对应功能。

  这个接口和按钮都去掉。
- **恢复点**：每条用户消息之前，即这条消息启动的那一轮开始之前。
- **记录范围**：只记文件工具（`edit_file`、`write_file`、`apply_patch`）的改动。改文件之前，按"会话 + 轮次 + 步骤"存下原内容和原来是否存在，归属落库；内容沿用 file-history 目录（`pkg/tool/state.go:1666`）。终端命令造成的改动不撤回，确认框里写明。
- **三种恢复方式**：
  - 代码和对话（默认）；
  - 只恢复对话；
  - 只恢复代码。
- **恢复代码**：这条消息之后各轮改过的文件，恢复到第一次改动之前的内容；之前不存在的文件删除。确认框列出文件和增删行数；当前内容与最后一次工具写入后的内容不一致的文件，标"之后被改过"，可以逐个取消勾选。
- **恢复对话**：在 transcript 里记一个回退点（做法同压缩边界或 context reset）。之后的行不显示、不进模型历史，但数据留在库里；这条消息放回输入框。
- **可撤销**：发出下一条消息之前都能撤销。恢复前先把当前文件内容存一份，撤销时写回，并去掉回退点；发出新消息后回退点固定下来。
- **两端**：web 在用户消息上悬停出现"回到这里"；TUI 用 `/rewind`，列出本对话的用户消息供选择，同样三种方式。两端共用 `pkg/turn` 里同一套实现。对话正在运行时不可用。
